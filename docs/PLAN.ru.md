# HSimRCL — план работ

## Зачем

Ассеты NVIDIA SimReady Central (OpenUSD, >2000 шт., физика, суставы, семантика) нужны прямо в Houdini.
Есть готовый браузер для Cinema 4D — SimRCL (Dead_wall, MIT) — с переносимым ядром и описанием порта
(`AGENTS.md` в его репозитории). Переносим ядро, Houdini-часть пишем заново.

## Принятые решения

- **Имя**: HSimRCL; пакет `hsimrcl`, ассеты `hsimrcl::*::N.0`.
- **Свой репозиторий** (`evgeni17/HSimRCL`, Apache-2.0), а не форк SimRCL: раскладка по правилам плагинов;
  файлы ядра SimRCL — под MIT с уведомлением (`NOTICE`, `third_party/SimRCL-LICENSE.txt`).
- **Ядро почти без правок**: только относительные импорты (иначе замороженные копии делили бы модули в
  `sys.modules`) и пути настроек на macOS. Так обновления SimRCL переносятся diff'ом; коммит —
  `SIMRCL_UPSTREAM`.
- **Контекст — Solaris (LOP)**, рендер — Karma. Ассет подключается reference'ом: физика, суставы, семантика,
  UsdPreviewSurface и `UsdTransform2d` сохраняются, отдельный бэкенд материалов не нужен.
- **Нода — Python LOP внутри HDA**, HDA собирается из кода (`hda_build.py`).
- **Папка загрузок общая с SimRCL** (`~/Documents/SRC by Deadwall/Assets`).
- **Без vendor**: USD берём из Houdini (`pxr`), сеть — `urllib`.
- **TLS**: у Python Houdini на macOS нет корневых сертификатов (путь машины сборщика SideFX). Проверку не
  отключаем; `hsimrcl.net.ensure_tls()` ставит opener с certifi из Houdini, только если в контексте по
  умолчанию нет ни одного сертификата.
- **Поворот/масштаб** — отдельные xformOp'ы `simready_up`/`simready_units` ПЕРЕД собственными операциями корня
  ассета (замена порядка операций стёрла бы их).
- **`!resetXformStack!` на частях** (ForgeCAD: `xformOp:transform:simulationWorld`): такие части игнорируют
  трансформы предков — створка двери оставалась Z-up. Переводим позу в локальную (L = M·T·inv(W родителя)),
  поза в координатах файла не меняется. Части внутри instance или с анимацией пропускаем с предупреждением.
  Это аналог шага SimRCL «Repair transforms», но причина другая (не импортёр, а сам файл).

- **Благодарность автору SimRCL** — обязательна в README (EN и RU) и в описании репозитория на GitHub:
  ссылки на https://github.com/denwerdan-arch/SimRCL и видео https://www.youtube.com/watch?v=xmf307dYwqM.
  Раздел не удалять при правках README; при публикации релиза — тоже упомянуть.

## Отвергнутые варианты

- Отдельный процесс с `usd-core` для разбора USD (как в C4D) — в Houdini есть `pxr`, разбираем в процессе.
- Перенос шагов SimRCL «материалы на instanceable», «UV-тайлинг» — обходы импортёра C4D; в Solaris не нужны
  (проверено на кресле: материалы и повтор текстуры ткани рендерятся в Karma как есть).
- Импорт в SOP/OBJ на первом этапе — пользователь выбрал Solaris; SOP — позже, если понадобится.
